# B 站完整版美劇搜尋工具 — 設計文件

日期：2026-11-11
狀態：待使用者核准

標記說明：**〔使用者〕** = 使用者親口決定的；**〔我的決定〕** = 設計者自行決定、使用者可推翻的；**〔偵查〕** = 2026-11-11 實測 B 站得到的事實。

## 1. 為什麼要做

使用者想在 B 站直接看完整、高清、未刪減的美劇。現在的痛點〔使用者〕：搜出來大多是剪輯版、叫人去網盤下載的引流影片、或集數不全的，每次都要找很久才找到一個完整的。

偵查證實了原因〔偵查〕：直接搜「绝命毒师」按播放量排，前 20 條全是解說、剪輯和無關影片，完整版完全被淹沒。

## 2. 目標

1. **搜尋**：輸入劇名 → 顯示該劇的「完整版」資源列表，按播放量從高到低排 → 點一條直接跳到 B 站播放。〔使用者〕
2. **最新上線**：不用輸入劇名，列出最近上傳到 B 站的完整美劇，按上傳時間從新到舊排。〔使用者〕
3. 主要在 iPad 上用。〔使用者〕

成功的樣子：輸入劇名後十幾秒內，第一屏就是可以直接點進去從頭看到尾的資源，不用再自己一條條點開確認。

## 3. 不做的事

- 不做網盤搜尋／下載。〔使用者說「沒有直接看的才用網盤」；偵查顯示直接看的資源存在，所以先不做——我的決定〕
- 不在工具內播放影片、不下載影片。點了就跳 B 站。〔使用者〕
- 不登入 B 站帳號、不存 cookie。〔我的決定；偵查證實不登入就能搜〕
- 不對外網開放，只在家裡 Wi-Fi 內用。〔使用者選擇放在這台電腦上〕
- 不存觀看紀錄、收藏、追劇進度。〔我的決定〕

## 4. 絕對不能發生的事（即使技術上能跑也算失敗）

- **把真的完整版悄悄篩掉。** 一集一段的完整版不可以被篩掉〔使用者明確要求〕。拿不準的一律降級到「可能不完整」區並寫出原因，不直接丟棄；被隱藏的也要能展開查看。
- **第一屏還是混著解說／剪輯／網盤引流。** 那就跟直接用 B 站沒差別。
- **把過期的失效連結當成結果顯示。** 這類資源常被下架〔偵查：有標題寫「第13次补档」〕，所以結果必須來自即時查詢，快取只能短暫。

## 5. 使用情境與形式

- 這台 Windows 電腦上跑一個小型本機網頁服務；電腦開著時，iPad 在同一個 Wi-Fi 下用 Safari 打開 `http://<電腦區網IP>:<埠>`，可加到主畫面。〔使用者選「放這台電腦上」〕
- 電腦上雙擊一個啟動檔就能開，啟動後在視窗裡顯示 iPad 要輸入的網址。〔我的決定〕
- 介面文字用繁體中文。〔我的決定，依使用者用語〕

## 6. 畫面（使用者已選 A：清單式）

草圖存於 `.superpowers/brainstorm/5195-1794394599/content/results-layout.html`。

- 頂部兩個分頁：**搜尋**｜**最新上線**。
- 搜尋分頁：搜尋框 + 按鈕；下方一行摘要「找到 N 個完整版 · 按播放量排序 · 已隱藏 M 個剪輯／解說／網盤引流」。「已隱藏 M 個」可點開查看被篩掉的項目與原因。〔可展開為我的決定〕
- 結果為**一行一條**：左側封面（角落顯示總時長），中間完整標題（不截斷）+ 一排標籤，右側播放量。
- 每條的標籤：
  - 涵蓋範圍：「全 N 季」／「第 N 季」／「第 N 季 1–9 集」
  - 形式：「一集一段 · 24 集」／「合併長片 · 22 段」／「合集 · N 支影片」
  - 畫質（1080P／4K…）、字幕（中字／雙語／純英文／未知）、上傳日期
- 列表底部一區「可能不完整（N）」，預設收合，項目半透明並標出原因（如「只有 1–9 集」）。
- 點任一條 → 開啟該影片的 B 站網址（iPad 上會跳 B 站 App 或網頁）。
- 最新上線分頁：同樣的清單，無搜尋框，按上傳日期新→舊，有「重新整理」按鈕與「上次更新時間」。
- 搜尋需要幾秒到十幾秒，期間要顯示進度（例如「正在查 B 站… 已找到 3 個候選」），不可空白卡住。

## 7. 「完整版」怎麼判斷

核心原則：判斷的是**「合起來是不是一整部／一整季」**，不是「單段夠不夠長」。〔使用者糾正後確立〕

### 7.1 B 站上完整版的三種形式〔偵查〕

| 形式 | 樣子 | 實例 |
|---|---|---|
| 合併長片 | 一支影片分數 P，每 P 是 6–12 集合成的 5–6 小時長片 | BV1G1s2zvEbF：22P、每 P 約 375 分鐘、總 8135 分鐘、1080P |
| 一集一段 | 一支影片分很多 P，每 P 一集（20–60 分鐘） | 使用者指出存在，不可篩掉 |
| 合集 | 每集（或每季）是獨立一支影片，由 UP 主串成合集（`ugc_season`） | BV1Ny6xBSEp4：屬於「摩登家庭 全11季合辑」 |

### 7.2 不是完整版的幾種〔偵查〕

| 類型 | 辨識訊號 |
|---|---|
| 解說／速看 | 標題含「解说、解读、一口气看完、速看、几分钟看完、详解、深度解析、回顾」；或總時長遠短於劇長（例：5 季只有 406 分鐘） |
| 剪輯／片段 | 單支且很短；標題含「混剪、片段、名场面、cut、合集（角色名）」 |
| 網盤引流 | 時長極短（<10 分鐘）卻自稱全集；標題／簡介含「网盘、自取、免费分享、私信、加群、公众号」 |
| 學英語筆記版 | 標題含「学英语、单词笔记、跟读、精讲」；每 P 只有幾分鐘 |
| 無關內容 | 分區是遊戲、美妝等；標題只是蹭關鍵字 |
| reaction 標題 | **注意：標題帶「reaction」不代表不是完整版**——偵查中多個真完整版用它規避審查，不可作為排除詞 |

### 7.3 判斷流程〔我的決定，建造者可調整細節〕

1. **撈候選**：對每個查詢，用多組關鍵字（劇名、劇名+全集、劇名+未删减 等）× 多個時長區間去搜。**不能只搜「60 分鐘以上」**，否則會漏掉一集一支影片的合集；還要搜 10–30、30–60 分鐘區間。
2. **粗篩**：只用搜尋結果裡的標題、時長、分區、簡介，先排除明顯的解說／引流／無關。
3. **查細節**：對剩下的候選逐一取詳細資料（分 P 數、每 P 時長與名稱、是否屬於合集及合集內各集、解析度、簡介）。
4. **合併**：同一個合集的多支影片合成一條結果；播放量取合集內各支加總。
5. **分級**：
   - **完整**：能確認涵蓋整季或整部（標題聲稱的集數與實際內容時長大致相符；單集平均時長落在正常一集範圍 18–70 分鐘）。
   - **可能不完整**：標題或分 P 名稱顯示只有部分集數、時長明顯不足、或訊號互相矛盾。附上原因。
   - **排除**：符合 7.2 的類型。計入「已隱藏」並可展開。
6. 標題中的規避寫法要先正規化再比對（例：「摩登-家庭」→「摩登家庭」；去除【】《》、空白、符號）。

判斷不可能百分之百準確，這是接受的；原則是**寧可多放進「可能不完整」，也不要誤刪**。

## 8. 最新上線

- 用一組通用關鍵字（如「美剧 全集」「美剧 未删减」「美剧 双字」）按上傳時間排序去搜，套用第 7 節同一套判斷。〔偵查：此法可查到近幾天上傳的《塔尔萨之王 第四季》《星期三 第一季》《怪奇物语 S1–S5》等，但混有動畫、國產劇、解說，需過濾〕
- 「是不是美劇」只能靠標題／標籤含「美剧」等字樣判斷，無法查證產地。〔我的決定〕英劇等歐美劇若標了相近字樣會混進來，可接受。
- 顯示最近一段時間（預設 30 天）內上傳的，新→舊。
- 結果快取約 30 分鐘；有手動「重新整理」。〔我的決定〕

## 9. 限制與現實（都來自偵查）

- **B 站會擋太頻繁的查詢**：連續快速請求會得到「成功但空結果」。工具必須在請求之間留間隔（約 1.5–3 秒）、遇到空結果要退避重試、並把同一查詢的結果短暫快取（約 10–15 分鐘）。一次搜尋因此需要幾秒到十幾秒。
- **搜尋接口需要簽名**：需先取得匿名訪客 cookie 與簽名金鑰再對參數簽名；偵查腳本已驗證可行（見 `recon.py` 的做法，建造時重寫，不沿用該拋棄式腳本）。此接口非官方公開 API，B 站改動時可能失效——出錯時畫面要明確顯示「B 站查詢失敗」及原因，不可顯示成「沒有結果」。
- **資源隨時會被下架**；工具不保證點進去一定還在。
- **看 1080P 以上通常要在 B 站自己那邊登入**，這是 B 站的規則，與本工具無關。
- **繁簡與譯名**：B 站內容是簡體、使用大陸譯名。工具會把輸入自動轉成簡體再搜〔我的決定〕。
- **英文劇名要和中文劇名查到一樣多**〔使用者，2026-11-11 追加〕：B 站用英文查常查不到。做法〔我的決定〕：搜尋前先向豆瓣的片名建議接口查一次別名，取得大陸中文譯名與英文原名，然後**用兩個名字一起搜**，判斷「是否與搜尋相關」時任一名字命中即可。〔偵查：`breaking bad`→绝命毒师、`Tulsa King`→塔尔萨之王、`the bear`→熊家餐馆；台灣譯名也能對應：`六人行`→老友记。`wednesday` 查無結果，故以 Wikidata 作後備。〕
  - 別名查不到或查詢失敗時，退回只用使用者輸入的名字搜，不報錯。
  - 畫面上顯示實際用了哪些名字（例：「同時搜尋：绝命毒师 / Breaking Bad」），讓使用者看得出有沒有對應錯。
  - 這代表劇名（僅劇名）會送到豆瓣／Wikidata。
- 字幕類型只能從標題字樣猜，猜不到就標「未知」。

## 10. 怎麼做（技術選擇，皆為〔我的決定〕）

- **語言與框架**：Python 3.12（電腦上已有，連同 uv）；後端用 FastAPI + httpx；前端是單一靜態頁面，原生 HTML/CSS/JS，不用前端框架、不需建置步驟。
- **結構**（各自職責單一，可獨立測試）：
  - B 站客戶端：取訪客 cookie、簽名、搜尋、取影片詳細資料、節流與重試。
  - 判斷器：純函式，輸入影片資料，輸出分級＋標籤＋原因。**不碰網路**，是測試的重點。
  - 搜尋流程：組合關鍵字、撈候選、呼叫判斷器、合併合集、排序。
  - 網頁服務：兩個資料接口（搜尋、最新上線）＋ 提供靜態頁面；搜尋進度以串流方式回報。
  - 快取：記憶體內、有時效即可，不需要資料庫。
- **服務綁定區網位址**以便 iPad 連線；首次啟動 Windows 防火牆會跳允許提示，說明文件要寫。
- **測試**：把偵查中遇到的真實案例存成固定樣本，對判斷器寫測試——至少涵蓋：合併長片、一集一段、合集、解說長片、短片引流、學英語筆記、標題帶 reaction 的真完整版、規避寫法標題。網路層不對真實 B 站跑自動測試。
- 專案目前是空資料夾、尚未 `git init`。
